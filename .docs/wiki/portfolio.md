# Portfolio de Stefano Mejias

## Propósito

Compartir un único enlace para que alguien pueda conocer el trabajo de Stefano, recorrer sus proyectos y abrir los que tienen una versión pública. El recorrido principal empieza en la presentación, continúa en los proyectos y termina en los canales de contacto.

## Punto de partida

[El sitio](../../index.html) es una página estática con [estilos](../../styles.css) y un [selector español/inglés](../../language.js) que guarda la preferencia en el navegador. Para previsualizarlo, abrir `index.html` en el navegador. El contenido principal está disponible aunque JavaScript esté desactivado.

## Diseño del sitio

- **Presentación breve.** Mostrar «Stefano Mejias», «Desarrollador de software» y un enlace «Ver proyectos». En escritorio, dejar que el catálogo empiece a verse en la primera pantalla. En móvil, mostrar la presentación y llevar al catálogo con un toque.
- **Catálogo como sección principal.** En escritorio, el sitio del Laboratorio Bellandi & Barreras encabeza el catálogo, seguido por una grilla de dos columnas. En móvil, los proyectos se apilan en una columna. El catálogo se puede filtrar por sitios web o sistemas. Las fichas aparecen con una transición escalonada al cambiar el filtro, salvo cuando se prefiere movimiento reducido. Las fichas pueden incorporar capturas reales cuando estén disponibles.
- **Ficha por proyecto.** Mostrar nombre, una frase sobre lo que resuelve y el aporte de Stefano cuando esté confirmado. Usar «Ver sitio» o «Ver repositorio» según el destino. Para un sistema interno, indicar «Proyecto privado» si se puede mencionar públicamente.
- **Dirección visual.** El portfolio usa un fondo claro y cálido, acentos terracota y fichas de colores suaves. Space Grotesk da carácter a los títulos y Manrope facilita la lectura de las descripciones. Al cargar, las partículas forman el monograma «SM» de Stefano Mejias. Se puede girar arrastrándolo o con el botón «Girar monograma». Con movimiento reducido se omite la animación de entrada. La terminal conserva su propio panel oscuro.
- **Contacto al final.** Conservar correo, GitHub y LinkedIn como accesos directos. Llevar las tecnologías a la ficha del proyecto cuando expliquen el trabajo.
- **Terminal de proyectos.** Los comandos `projects` y `project N` leen nombres, descripciones y enlaces del catálogo. `help` explica los comandos y `clear` limpia la salida. Los botones rápidos se pueden usar desde el celular.

## Cómo sumar un proyecto

Completar estos datos a medida que estén disponibles. Una ficha puede publicarse con el nombre, una descripción respaldada y un enlace público o una indicación de que el proyecto es privado.

| Dato | Qué registrar |
| --- | --- |
| Nombre y propósito | Nombre público y qué puede hacer una persona con el sitio o sistema |
| Participación | Qué diseñó, programó, integró o mantiene Stefano |
| Enlaces | Sitio, demo o repositorio que se puedan compartir |
| Captura | Vista real autorizada, con texto alternativo y datos sensibles ocultos |
| Tecnología o resultado | Solo cuando aporte contexto y haya una fuente que lo respalde |

## Criterios para dar el rediseño por listo

- Una persona puede llegar al catálogo desde la portada, identificar cada proyecto y abrir sus enlaces públicos.
- El sitio funciona en móvil y escritorio, con navegación por teclado y contenido visible sin animaciones.
- El selector de idioma, si se mantiene, traduce la página en ambos sentidos.
- Las fichas tienen descripciones concretas. Las afirmaciones sobre uso, métricas o resultados aparecen únicamente cuando están respaldadas.
